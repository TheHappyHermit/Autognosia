# Project Work

Handle project lifecycle including closing, troubleshooting journals, purchasing decisions, restart summaries, failed approaches, next actions, and closure checklists.

## Project Closing

When a project reaches completion:

1. Update project page status to `completed`
2. Fill in closure checklist:
   - Objective achieved?
   - Definition of done met?
   - Lessons learned recorded?
   - Failed approaches preserved?
   - Next actions identified?
3. Create restart summary for future reference
4. Move to `active-wiki/projects/archive/` if no longer active

## Troubleshooting Records

When troubleshooting hardware, software, infrastructure, or the Autognosia itself, preserve:

- Observed symptom
- Environment
- Current verified state
- Initial hypotheses
- Tests performed
- Results
- Disproven explanations
- Changes made
- Verified fix
- Before-and-after measurements
- Remaining uncertainty
- Rollback or recovery information
- What not to repeat
- Next action

Do not save every conversational exchange. Save the verified state, meaningful tests, failed approaches, and final result.

## Purchasing Decisions

When evaluating a purchase (hardware, software, services, subscriptions), preserve:

- Requirements
- Constraints
- Things already owned
- Exact candidate models
- Current prices and date checked
- Included accessories
- Compatibility
- Space, power, and environmental requirements
- Known defects and concerns
- Warranty and return terms
- Required additional purchases
- Real total cost
- Expected resale value
- Reason to buy now
- Reason to wait
- Rejected alternatives and why
- Current recommendation
- Final decision
- Post-purchase outcome

Temporary prices and current product information must be dated.

## Next Actions

After meaningful project work, identify the smallest useful next action.
