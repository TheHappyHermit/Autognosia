# RESEARCH delivery checklist
Use this when delivering a new RESEARCH.md top entry.

- Topic inherited from the first `[⏳]` grep hit.
- Scientifically valid technical content with concrete architecture, formulas, data model, UI, edge cases, regulated-footprint, and testing perspective.
- Append-only delivery: never overwrite RESEARCH.md.
- Preserve the prior RESEARCH.md content; draft the new entry in `/tmp/` first when needed.
- Update AGENDA.md for the same topic only: mark `[⏳]` -> `[✅]` and append discovered sub-topics on that line.
- Do not add unrelated agenda items.
- Do not erase RUN_COUNTER.md history; only append a new Run header or patch the newest header.
- Mark progress in `todo` whenever WORK>5 tool calls.
