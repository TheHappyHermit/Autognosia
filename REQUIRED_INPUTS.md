# Required Inputs

This file is referenced by [INSTALL.md](INSTALL.md). Fill in these values during initial setup.

```markdown
# Required Inputs

Configure the following before deploying services:

- [ ] **LLM Provider API Key** — For Honcho's deriver (user-model derivation)
  - If Hermes is setting up the system automatically: Honcho will inherit the same provider and API key that Hermes is already configured to use (from your Hermes `.env` file at `~/.hermes/.env`). No extra input needed.
  - For manual setup, choose one:
    - Local endpoint (LM Studio, Ollama, vLLM): set `HONCHO_LLM_BASE_URL` and `HONCHO_LLM_MODEL`
    - Cloud provider: set `HONCHO_LLM_PROVIDER` and `HONCHO_LLM_API_KEY`
  - If not configured: Honcho runs in read-only mode (no derivation)

- [ ] **SearXNG Secret** — Auto-generated by Hermes if not provided
  - Command: `openssl rand -hex 32`
  - Stored in `docker/.env` as `SEARXNG_SECRET`

- [ ] **GBrain API Keys** — For semantic search and fact extraction
  - ZeroEntropy: `ZEROENTROPY_API_KEY` (default embedding + reranker)
  - OpenAI: `OPENAI_API_KEY` (fallback for vector search)
  - Anthropic: `ANTHROPIC_API_KEY` (optional, improves search quality)
  - Note: These are read from your Hermes `.env` file automatically during auto-setup. For manual setup, fill them in `docker/.env`.

- [ ] **GitHub Token** — For automated config backups (optional)
  - If not provided, backup scripts skip git push

- [ ] **Researcher Profile Model** — Which model handles web research
  - Default: inherits global model from Hermes config
  - Can be a cheaper model (research is high-volume)
```

## How to Use

### Auto-Setup (Hermes does the work)

1. Tell Hermes: "Set up the Autognosia from the repository"
2. Hermes reads your existing `.env` file at `~/.hermes/.env` and auto-fills the provider/API key configuration
3. Hermes generates the SearXNG secret automatically
4. Hermes prompts you only for inputs it cannot infer (e.g., GBrain API keys if not present)

### Manual Setup

1. Open `docker/.env.example` and copy it to `docker/.env`
2. Fill in the required fields
3. Follow the steps in [INSTALL.md](INSTALL.md)
4. Restart affected services after configuration changes
